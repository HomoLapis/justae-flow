# JustAE Flow

<!-- PLACEHOLDER (author): one-line tagline. -->

<!-- PLACEHOLDER (author): presentation text — what JustAE Flow is, why it exists, the comparison with
     the subscription plugins it replaces. Keep the technical sections below as they are. -->

**Generative AI inside open-source compositing and image editing, on your own ComfyUI.** Markers and placeholder
layers in [EffectCraft](https://github.com/storytold/effectcraft), and selections and placeholder layers in
[PhotoCraft](https://github.com/storytold/photocraft), become a storyboard; every card is generated by a ComfyUI
workflow and lands back in the project at its place, as a new version — never over the old one.

## What it does

JustAE Flow is **JustAE Flow 2** — the After Effects panel that runs any ComfyUI workflow against the timeline —
brought to EffectCraft. The interface is Flow 2's own: a **Flow window** with three tabs, opened from a panel docked in
EffectCraft.

| Tab | What you do in EffectCraft | What Flow does |
|---|---|---|
| **Workflow** | — | lists the workflows on your ComfyUI (its workflow folder, searchable), reads each graph and builds a form from it; the comp fills canvas size, length and frame rate into the fields that take them. *Edit in ComfyUI* opens the editor in its own window with that workflow on the canvas; Ctrl+S there saves back to the same file. The *Pipeline* lists the stages of a production (draft or final presets, lossless output profiles) and whether their nodes are installed |
| **Marker** | add comp markers in **pairs** around each gap to fill | one shot per pair, in time order; the clip comes out exactly as long as the gap. Or one clip at the playhead |
| **Storyboard** | block the cut out with **adjustment layers** (eye on) | one shot per placeholder: its in and out points are the slot, its label colour comes back on the generated clip, and its eye is switched off once the clip is placed |

Every shot row has its own workflow dropdown and, opened, its own prompt and that workflow's inputs: a frame or the
work area from the comp, an attached file. Shots run in series with live progress and previews; each generation gets
its own folder next to the project (`<Project>_JustAE-Flow/<Comp>/shot_001_…/`) with its inputs, its output, the
workflow that ran and a `job.json` of every value used. *Save setup / Load setup* keep a shot list as a file; the
history lists every run.

The panel in EffectCraft (**Window ▸ JustAE Flow**) opens the Flow window, shows what it will work on (marker shots and
placeholders in the active comp), adds a marker pair or a placeholder at the playhead, and runs the **layer tools** on
the selected clip:

| Layer tool | What it does |
|---|---|
| Cut out a subject (SAM 3) | tracks what you name through the clip; a matte layer above becomes the clip's luma track matte — the clip's pixels are untouched |
| Reframe, generate the new space (Wan VACE 14B, or the 1.3B draft) | a new comp in 9:16, 4:5, 1:1 or 16:9 where the space the clip does not cover is generated around it, and the clip sits on top, untouched, with a soft edge. Clips longer than one run go through in runs that carry on from each other |
| Auto crop (SAM 3) | crops to the new aspect instead: the clip at 100% in a new comp, with Position keyframes that follow the subject |
| Upscale ×2 (SeedVR2) | laid exactly over the source, which is switched off — not deleted |

**Where workflows run** (Flow window ▸ Settings ▸ Resources): your **local ComfyUI**, **Comfy Cloud**, your own
**Comfy API deployments**, or your ComfyUI behind **`comfy-api-proxy`** — chosen per task, with one platform API key
for all of Comfy's side, the credit balance in the header and an estimate under every Generate button (see
[Resources and credits](#resources-and-credits)).

PhotoCraft keeps its own storyboard (selections and placeholder layers, at http://127.0.0.1:5199/storyboard/, where the Flow
window goes by itself when Settings ▸ App is PhotoCraft); a Flow window for PhotoCraft is not in this version.

## Workflows

All bundled workflows are **official ComfyUI templates** with **open weights**, converted to the API format by
`scripts/build-workflows.ts` (no hand-edited graphs). No partner nodes, no closed APIs.

| Id | Template (comfyui-workflow-templates 0.11.76) | Task | Weights licence |
|---|---|---|---|
| `ltx25-t2v` | `video_ltx2_5_t2v` | text → video with sound | LTX-2 Community License |
| `ltx25-i2v` | `video_ltx2_5_i2v` | frame under the marker (or an attached image) → video | LTX-2 Community License |
| `zimage-t2i` | `image_z_image_turbo` | text → image | Apache-2.0 |
| `seedvr2-upscale` | `utility_seedvr2_3b_int8_upscale_video` | video ×2 restoration upscale | Apache-2.0 |
| `birefnet-rmbg` | `utility_birefnet_remove_background` | still → cut-out with alpha | MIT |
| `sam3-matte` | `utility_video_segment_sam3` | clip + subject name → tracked matte video (luma) | SAM License (Meta) |
| `sam3-reframe` | `utility_video_segment_sam3` | clip + subject name → a small mask per frame, for the auto crop | SAM License (Meta) |
| `vace-reframe` | `video_wan_vace_outpainting` | clip in a new aspect → the space around it generated (Wan2.1 VACE 14B, 720p) | Apache-2.0 |
| `vace-reframe-draft` | `video_wan_vace_outpainting` | the same on the template's 1.3B model, 480p, for a quick look | Apache-2.0 |
| `qwen-edit` | `image_qwen_image_edit_2511_int8` | image + prompt → edited image (PhotoCraft selections) | Apache-2.0 |
| `seedvr2-upscale-image` | `utility_seedvr2_3b_int8_upscale_image` | image restoration upscale | Apache-2.0 |

The SAM 3 template detects the subject frame by frame and only previews the mask; the build replaces the detection
with the core nodes `SAM3_VideoTrack` + `SAM3_TrackToMask` (one subject stays the same subject through the clip)
and saves the result. The auto crop is not done in ComfyUI: SAM 3 only says where the subject is; JustAE Flow
builds the new comp on the original footage, so nothing is resampled and the framing stays editable.

The generative reframe starts from the official Wan2.1 VACE outpainting template. The build cuts the clip to the
frames one run holds and scales it into the generation frame, so the padding is exactly the new space; JustAE Flow
sets the sizes per aspect. The template speeds the 14B model up with the CausVid LoRA, whose weights are CC BY-NC 4.0
(non-commercial); `vace-reframe` uses lightx2v's Apache-2.0 4-step distillation LoRA for Wan2.1 14B instead, and
`vace-reframe-draft` runs the 1.3B model without a LoRA, on the template's default sampler settings. A clip longer
than one run (125 frames) is split into runs where each one starts from the last 8 frames the one before generated,
and the runs are joined into one video in ComfyUI.

Each `workflows/<id>.json` manifest names the node fields the host fills in (prompt, image, size, length, seed),
the model files with their download URLs, and the licence. If your ComfyUI has another precision of the same
weights (for example the LTX-2.5 transformer in nvfp4 instead of int8), JustAE Flow uses it and says so on the card.

```bash
npm run verify:workflows -- http://127.0.0.1:8188   # what your server can run, and the URLs of what is missing
```

## Requirements

- **Node.js 22.18 or newer** (runs the TypeScript server directly; no build step for it).
- **EffectCraft 0.11.1 or newer**, started with its control channel: `effectcraft --control 9877`
  (Windows: `"C:\Program Files\EffectCraft\effectcraft.exe" --control 9877`). The channel listens on
  127.0.0.1 only and is off unless you start it this way.
- **PhotoCraft 0.12 or newer** (optional, the other host), started with its control channel, a token file and an
  automation folder — PhotoCraft may read and write files only there, so JustAE Flow keeps that document's storyboard
  and images there too:
  `photocraft --control 7878 --control-token-file <token file> --automation-read-root <folder> --automation-write-root <folder>`
  (the setup guide prints the exact line; the token file is created by PhotoCraft and read by JustAE Flow).
- **ComfyUI 0.38 or newer** with the official templates package (it ships with ComfyUI), reachable over HTTP —
  local, on your network, or in your own cloud. The LTX-2.5 workflows need a GPU with 16 GB or more; the Wan VACE
  14B reframe is meant for a cloud GPU with 48 GB or more (on a 16 GB card it runs offloaded, at 6 to 12 minutes
  per step for 125 frames).

### ComfyUI in your own cloud

A ComfyUI behind a router that asks for a bearer token (for example a self-hosted deployment on Modal, where a GPU
worker starts for each job and scales back to zero when idle) works as it is: put its address in **Settings ▸
ComfyUI address** and its token in **Access token**. The token is sent as `Authorization: Bearer …` (and as
`token=` on the WebSocket, which cannot carry headers); it is kept in your user folder and never sent to the browser.
If the router publishes a GPU menu (`/manager/monitor/pricing`), **GPU for jobs** lists it with prices, and the
choice goes with every job as `X-Comfy-GPU`. Model files the router does not have are reported on the card with
their download URLs, like on a local ComfyUI.

### Resources and credits

**Settings ▸ Resources** in the Flow window lists the places a workflow can run. Everything there is kept by the
JustAE Flow server in your user folder — the registry in `resources.json`, the platform API key in
`comfy-api-key.txt`, the proxy's token in `comfy-proxy-token.txt` — never in the project, the repository or the
Flow window's storage. The window sends a key once and gets back only whether one is set and its last four
characters.

| Resource | Address | Protocol, key | Cost |
|---|---|---|---|
| **Local ComfyUI** | `http://127.0.0.1:8188` (the address the settings already had) | ComfyUI's own HTTP + WebSocket protocol; no key | your GPU |
| **Comfy Cloud** | `https://cloud.comfy.org` | Comfy API v2 for jobs (`Authorization: Bearer`); the v1 Cloud API (`X-API-Key`) for the node catalogue, the model folders and the billing report | credits for GPU time |
| **Deployment** | `https://<deployment>.run.comfy.app` — `comfy deploy status` prints it | Comfy API v2, the same key | credits per second of GPU while a worker runs |
| **Your ComfyUI via [`comfy-api-proxy`](https://docs.comfy.org/development/comfyui-server/api-proxy)** | `http://127.0.0.1:8189` | Comfy API v2; none, or the proxy's `--token` | your GPU |

One key — from [platform.comfy.org ▸ API Keys](https://platform.comfy.org/profile/api-keys) — serves Comfy Cloud
and your deployments (docs.comfy.org, *Comfy API v2 Overview* ▸ Base URLs; *v1 Cloud API Overview* ▸
Authentication). It goes over https only, or over plain http to this machine.

**Comfy API v2 runs on the server, through the official SDK** (`@comfyorg/sdk` 0.5.0): inputs go up as assets
addressed by their blake3 hash (bytes the platform already has are not sent again), each Generate is one submission
under one `Idempotency-Key` (a 429 — queue full, or a deployment still starting a worker — is retried under the same
key for up to 10 minutes, nothing else is), the job is polled every 2 seconds, outputs come down through the server.
The SDK takes its base URL only from the `COMFY_BASE_URL` environment variable, read in its constructor
(`src/sdk/client.ts`); JustAE Flow builds one client per resource and sets the variable only for the instant of
construction.

**Where each task runs.** A table in the same page sets, per task, Local, Cloud, a deployment, the proxy or
**Auto** (the defaults: video Auto, image Local, generative reframe Cloud, reframe draft Local, upscale Cloud,
matte Local, slow motion Local, restyle Auto). Auto is Local when the local ComfyUI has the workflow's nodes and
models, else the first other resource that has them. A row on a resource that is not set up falls back to Auto, so
without a key everything stays local. The resource on the **Generate** button overrides the table for a batch; the
EffectCraft panel says where its layer tools run. Each shot's `job.json` records the resource, why it was chosen,
the execution time and the derived credits.

**What a resource can run** is probed and kept ten minutes: on the local ComfyUI its `/api/object_info` (node classes
and the model files its loaders offer, as `npm run verify:workflows` does); on Comfy Cloud the v1 `/api/object_info`
(with the key) and `/api/experiment/models/{folder}` (public). A deployment and the proxy have no node catalogue on
v2 (measured on `comfy-api-proxy` 0.1.6: `/api/object_info` answers 404), so they are "unknown until a workflow has
finished there". What we found on Comfy Cloud is in [docs/CLOUD_PROBE_2026-10-25.md](docs/CLOUD_PROBE_2026-10-25.md).

**Credits.** When the resource of the next Generate bills, the header shows the account's balance, read from the v1
billing report `GET /api/billing/usage/timeseries` (`summary.balance`, in **cents** despite the `_micros` suffix,
converted at 211 credits = 1 $; openapi-cloud.yaml and comfy.org/cloud/pricing). That report is drawn from invoices,
not live usage, so the balance always carries the time it was read and is read again after every job on Cloud or a
deployment — when it has not moved yet, the window says so. It is cached five minutes.

**Estimates and costs are derived, never stated.** No endpoint returns a job's price (the v2 job carries
`metrics.execution_ms`; SDK `types.gen.d.ts`). So, under every Generate button:

- after a run: execution time × the GPU's rate — Comfy Cloud runs on the RTX PRO 6000, **736.39 credits per GPU
  hour** (0.2045 per second); a deployment bills at the rate of the GPU it was deployed on: RTX PRO 6000 736.39,
  H100 1,314.53, H200 1,626.81, B200 2,369.53 credits/h (comfy.org/cloud/pricing, read 25 Oct 2026) — chosen in its
  card;
- before a run: the fastest and slowest earlier runs of the same workflow on the same resource and GPU, scaled by the
  slot for video, always with "≈" and its basis ("based on 3 runs on RTX PRO 6000"), or the rate alone when there
  is none ("first run: 12.3 cr/min"). A slot longer than any run on record is flagged. A Storyboard series shows the
  sum. When the balance is under twice the estimate, a yellow line offers to switch to Local; a `402
  insufficient_credits` ends the job with the same offer.

The run history the estimates come from is `runs.json`, in the same user folder.

**A deployment bills while a worker runs**, not per job: deployed with `--min 0` it scales to zero between jobs (the
next job waits for a worker); with `--min 1` a worker stays up and bills while idle — its card says how much a day.
`comfy deploy stop` ends the charge and keeps the URL. JustAE Flow does not build, release, deploy, start, scale or
stop anything on the platform: it talks to an endpoint you already have ([quickstart](https://docs.comfy.org/development/serverless/quickstart)).

What is different on v2: workflows go in API format (the Workflow tab still reads your local ComfyUI's folder, and
its graph is what goes to the cloud); no live previews; on a deployment, only the nodes and models of the build it
was released from. To try v2 for free, run `pip install comfy-api-proxy` and `comfy-api-proxy` next to your ComfyUI:
it speaks the protocol a deployment speaks.

`npm run probe:cloud` (`scripts/probe-cloud.ts`) asks Comfy Cloud what it offers this account — read-only, no job,
no credit — and prints the node and model tables.

## Install and run

```bash
git clone <REPO_URL> justae-flow && cd justae-flow
npm run setup        # npm install + build the UI + enable the pre-commit secret scan
npm run launch       # the server, EffectCraft with its control channel, and the Flow window docked beside it
```

On Windows, double-click **JustAE Flow.cmd** instead; `node scripts/launch.ts --shortcut` puts a shortcut to it on
the desktop. EffectCraft opens its control channel only when it is started with `--control 9877`, so the launcher
starts it that way. An EffectCraft that is already open without it cannot be joined: the launcher says so and leaves
it alone — save your work, close it, and launch again. `npm start` runs the server alone (http://127.0.0.1:5199);
the PhotoCraft storyboard at `/storyboard/` has a setup guide that connects the app and ComfyUI and runs a test image.
Settings are stored in your user folder (`%APPDATA%\JustAE Flow`, `~/Library/Application Support/JustAE Flow`,
`~/.config/JustAE Flow`), never in the project or the repository. `.env.example` lists the variables that override them.

### The Flow window, docked

EffectCraft docks only ScriptUI panels — it has no web panels like After Effects' CEP — so Flow 2's interface runs in
an app window of Edge or Chrome. On Windows it opens at EffectCraft's right edge, at full height, with EffectCraft
narrowed to make room, and it follows EffectCraft when EffectCraft is moved, resized, minimized or restored. Drag it
away to undock it; **Open JustAE Flow** in the panel docks it again, and never opens a second one. On macOS and Linux
it opens as a window of its own, next to which you place EffectCraft yourself.

### The panel inside EffectCraft

1. In EffectCraft: **Preferences ▸ Scripting & Expressions ▸ Allow Scripts to Write Files and Access Network**
   (the panel talks to the JustAE Flow server on 127.0.0.1).
2. **File ▸ Scripts ▸ Install ScriptUI Panel…** and pick `extensions/effectcraft/JustAE Flow.jsx`.
3. **Window ▸ JustAE Flow** opens it; dock it wherever you like. It shows whether the server and EffectCraft's control
   channel are up, opens the Flow window, adds marker pairs and placeholders, and runs the layer tools.

## Using it

1. In EffectCraft open a composition. For the **Marker** tab add markers in pairs around each gap (or press
   *+ Marker pair* in the panel); for the **Storyboard** tab add adjustment layers (*+ Placeholder*), move and trim them.
2. In the Flow window pick a workflow in the **Workflow** tab — or per shot, in its row.
3. Open a row: the prompt, and that workflow's inputs. Fields the comp can fill say *from comp*.
4. **Generate clip** runs the ticked shots in series and places each clip at its slot.

## How it works

```
 EffectCraft ──(control channel, JSON lines, 127.0.0.1:9877)──┐
   └ JustAE Flow panel (ScriptUI) ──(HTTP)──┐                 │
                                            │                 │
                         JustAE Flow server (Node, 127.0.0.1:5199)
                         · host bridge: Flow 2's host functions run inside EffectCraft (script.run)
                         · files, HTTP and WebSocket relays for the Flow window (session token)
                         · layer tools and the PhotoCraft storyboard: engine, queue, versions
                                                               │
 Flow window (React, Flow 2's interface) ──(HTTP + SSE)────────┘──(HTTP/WS, SDK)── ComfyUI, Comfy Cloud, deployments
```

Flow 2 ran inside After Effects as a CEP panel: CEP gave it Node (files, HTTP without CORS) and ExtendScript (the
host). Here the same interface runs in a window and the server stands in for both:

- **The host.** EffectCraft's scripting follows After Effects scripting, so Flow 2's host file
  (`extensions/effectcraft/flow-host.jsx`) runs inside EffectCraft as it is, through the control channel's
  `script.run`: markers, adjustment layers, import at a time with the label colour, frame capture
  (`saveFrameToPng`), work-area render, trims, the native Save/Open dialogs. Two changes: the project name
  (`.ecproj`) and the temp folder, which EffectCraft's scripting does not expose and the server provides.
- **Files** go through the server, limited to your user folder and the temp folder; **HTTP** to ComfyUI or a cloud
  API goes through a relay, so no CORS and no token in a browser request; the ComfyUI **WebSocket** is relayed as
  server-sent events. Every one of these routes wants the session token the server writes into the page, and a request
  that names another origin is refused: any web page can reach 127.0.0.1, none other can read the token.
- **Lossless masters** (ProRes 4444, PNG 16-bit) are made by the server with ffmpeg, which must be on the PATH.

```
client/      the Flow window (Flow 2's interface; bridge/ and lib/ are the parts that talk to the server)
extensions/  the EffectCraft panel and the host file
core/        host-independent: ComfyUI client, workflow conversion, manifests, storyboard types, reframe planning
hosts/       one adapter per host app for the engine (effectcraft: a timeline, photocraft: a canvas)
server/      the host bridge and relays, the window dock, the engine (layer tools, PhotoCraft storyboard), settings, HTTP API
workflows/   bundled workflows for the layer tools and PhotoCraft: <id>.json manifest + <id>.api.json graph
scripts/     launch, build-workflows, verify-workflows, verify-effectcraft, selftest, scan-secrets
```

## Privacy and network

JustAE Flow listens on 127.0.0.1 only. It talks to things of your choosing: your EffectCraft or PhotoCraft
(loopback; PhotoCraft also with its token) and the resources you set up — your ComfyUI, and, once you add the API
key, Comfy Cloud (jobs, node catalogue, model folders, billing report) and the deployment addresses you paste. No
telemetry, no account of its own, no other network access.

## Development

```bash
npm run typecheck
npm run selftest                 # offline: fake ComfyUI + in-memory hosts, end to end
npm run verify:workflows         # bundled workflows against a live ComfyUI (read-only)
npm run verify:effectcraft       # the storyboard as the engine sees a live EffectCraft
npm run probe:cloud              # what Comfy Cloud offers this account (read-only, no job, no credit)
npm run workflows:build          # regenerate workflows/*.api.json from the official templates
npm run scan:secrets             # also runs as the pre-commit hook
npm run dev                      # UI dev server on :5198 (proxying the API on :5199)
```

## Known limits

- One host at a time: switch between EffectCraft and PhotoCraft in Settings ▸ App.
- PhotoCraft's control channel has no way to pass pixels in memory, so images cross through files in its automation
  folder; a selection edit sends the whole visible image and keeps the change to the selection with a mask.
- Image-to-video uses the frame under the marker as the comp shows it; attach an image to a card to use another.
- Upscale, background removal, subject matte and reframe take their input from the layer's own file; a placeholder or
  a marker cannot feed them.
- The subject matte follows the subject's shape as SAM 3 sees it; hair and motion blur get a hard edge. Refine it in
  EffectCraft (the matte is an ordinary layer) or generate a new version with another subject word.
- The auto crop does not invent pixels: a 9:16 comp from 16:9 footage is as tall as the footage. The generative
  reframe does: its new space is generated at 720p (14B) or 480p (draft) and scaled to the 1080-wide comp, so it is
  softer than the clip in the middle.
- A generative reframe takes time: on a 16 GB GPU the 1.3B draft needs about 6 minutes for 125 frames at 480p; one
  card makes at most four runs (about 20 s of a 24 fps clip).
- Live previews depend on the model: ComfyUI sends them while sampling (`preview_method: auto` per job).
- Storyboards written under the project's former name (`*.shiftfield.json`) are still read, where they are.
